# Results, Red Sea Breakout 1988 (Intro 01), Sonnet 5.5 (low effort) on both sides

Blue = USS Yorktown + E-2C (Player taskforce), Red = Yemeni boats, MiG-21s and coastal sites (game AI helpers).
12 decision windows, 300 game-seconds each, 4x time compression. Costs are the Claude CLI's reported cost.

| Run | Setup | Result | Notes |
|---|---|---|---|
| 1 | no `engage`, briefing map for Blue | Red win, Yorktown lost ~16 min in | Blue never changed speed (13 kn), re-sent "weapons free" each window |
| 2 | no `engage`, + 3 standing instructions for Blue | Red win, Yorktown lost ~10 min in | Blue sped up once, still sailed into the boat cluster |
| 3 | `engage` available to both | Blue win, 13 kills / 0 losses | Blue 14 of 52 engage orders accepted, 38 refused (dead tracks) |
| 4 | same | Blue win, 10 kills / 0 losses | 13 of 43 accepted |
| 5 | + dead-track removal, receipts, weapon economy | Blue win, 10 kills / 0 losses, ended at window 6 | 14 of 19 accepted, 5-inch gun fired |

## Findings

- **Why Blue lost without `engage`:** a "weapons free" posture only lets the unit's own AI fire when *it* decides to; Blue's ships scored almost
  nothing while Red's AI-driven boats fired freely. With a direct order (`AI.AutoAttackByClick`, the same call as the player's click-to-attack)
  the same ship killed boats within a minute. Confirmed live before any match was run.
- **The game keeps a destroyed object's track flagged `live`** (age keeps growing), so commanders kept ordering shots at dead tracks until the
  runner removed them (learned from the game's own refusals) and labelled old tracks STALE.
- **`emitters active` only affects units that have a search radar**; radar state updates only when game time advances, so a paused-window
  readback of `radar_on` is not reliable.
- **Token cost:** Sonnet at low effort answers tersely (~300-1,500 output tokens per call). Haiku at low effort produced ~8k per call, so it cost
  more per match than Sonnet in this setup.
- **Red's play barely changes between runs** (swarm the cruiser's exact position); its boats spend ~800-1,000 gun rounds without a kill.
- **Mission end:** the game's own end-of-mission flag (`/truth.mission_ended`) is authoritative; the runner scores from it.

## Limits

Five games total, one scenario, runs 1 and 2 differ from 3-5 on purpose (the setup changed). Not a balance study. The sigma units of track
position uncertainty and the in-game marked-circle position were not independently verified.


## Gulf of Sidra (1986), Sonnet 5.5 (low effort) on both sides

Blue = Saratoga carrier group + Ticonderoga surface group; Red = Libyan boats, SAM/AAA sites, MiG-25P/F1E. Win = four designated Libyan boats destroyed AND the SA-5 radar destroyed or without guidance; lose if any Blue ship is destroyed.

| Run | Setup | Result |
|---|---|---|
| 1 | 16 x 240 s, no relation field, no launch | no verdict; Blue lost 3 aircraft, Red passive after setting every unit to tight |
| 2 | + relation, `next_check_s`, ETA/damage/fuel, aircraft weapon honored | no verdict; Blue's A-6s died ~17 nm short of the SA-5; the budget was window count, so only ~65 game minutes were played |
| 3 | game-time budget (3.5 h) | stopped early by the user; all combat aircraft lost, nothing happening |
| 4 | + `launch` / `rtb` and the carrier air wing in the prompt | **Blue victory declared by the game**, 0 Blue losses, 15.5 kills; $1.10 total |

Findings:
- **The model was not the limit; the interface was.** The carrier held SEAD aircraft (A-7E/A-6E with HARM) and an EA-6B jammer that no commander could launch or even see. Once `launch` and an air-wing listing existed, the same commander ran a clean SEAD-then-sink campaign.
- **Aircraft `engage` without a weapon only designates;** the aircraft AI then flies a close-in run. With a named weapon the task fires once the target is in that weapon's range. Weapons are target-class specific (an AGM-84 Harpoon cannot engage a SAM site, a HARM was refused against a non-emitting SA-5 radar), so the weapons list shows what each weapon can hit and refusals name the usable alternatives.
- **Red's commander is not the Red side's fighting power:** the game's AI units fire on their own; a commander blanket-setting everything to "tight" in window 1 mostly just gave away its orders. The prompt now says to keep scenario postures.
- **Window count is the wrong budget:** commanders asked for short windows, the shortest request wins, and 24 windows covered the same 65 game minutes as 16. The runner now limits game time.

## Sub Duel, Denmark Strait (1985): Baltimore (Blue) vs Alfa (Red)

New plugin orders for submarines: `depth` (seven presets), `sonar` (active/passive), `decoy`; a `sub` status block (depth, battery, snorkel, preset depths in feet). The plugin also sets the game's `DM._subAIAppliesToPlayer` so the player side's boat gets the same sub AI (contact analysis, torpedo evasion) as the AI side. The generator now tells Blue about the game's drawn escape zone (lat/lon circle); Red is not told.

| Run | Blue | Red | Result | Cost (Blue / Red) |
|---|---|---|---|---|
| 1 | Sonnet | Sonnet | Blue victory (game verdict) after 31 game min, 0 losses, margin +1.0 | $0.19 / $0.15 |
| 2 | Sonnet | Haiku | stopped by the user at window 49 (82+ of 120 game min), no kills, no result | about $0.55 / $1.2 |

- Run 1: Blue held a quiet passive approach, identified the Alfa at ~13 nm, fired Mk48s with `engage`, and waited about 20 game minutes for them to arrive. Red never detected the Baltimore until a torpedo was close, then used a noisemaker and dived; the game declared Blue's victory. No invalid or refused orders. Single match.
- Run 2 was not scored and is not a model comparison (one unfinished match). It shows that range matters: Blue chased an Alfa that was ~34 nm away against a 27 nm torpedo range.
- Plugin quirk: the depth "setting" field is not meaningful until a depth order is given (hidden from the models); battery reads 0 on nuclear boats.
